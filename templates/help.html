ABOUT PHISHSHIELD

About and help

PhishShield is an MCA cybersecurity education project for campaign-based awareness exercises and explainable email risk assessment. It uses Flask, SQLite, HTML, CSS, JavaScript and a Python rule engine.

Ethical use and privacy

  • Use fictional messages only, with authorized participants and an instructor-led learning goal.
  • PhishShield sends no email, opens no external destination and never requests passwords or other sensitive information.
  • Participant IDs are random local identifiers; do not use results to shame or rank individuals.
  • Instructor campaign management, research, and analytics require an instructor login. Configure a strong secret key and hashed instructor password before deployment.

Instructor workflow

  1. Review the email library and supporting research.
  2. Create a campaign, assign messages, and activate it when ready.
  3. Share the local invitation path with participants.
  4. Review persisted campaign events and aggregate dashboard metrics.

Participant workflow

  1. Open the campaign invitation and join with a generated pseudonymous identifier.
  2. Present each assigned message through the explicit action button.
  3. Report it as phishing, mark it legitimate, or choose the safe simulated interaction.
  4. Review feedback and continue until the exercise summary appears.

Interpreting email analysis

The Python rule engine produces an explainable heuristic score from supplied text and metadata. A score is not a probability, identity check, or guarantee. Missing evidence is reported as a limitation.

URLs are inspected only as text. PhishShield does not resolve or visit them, and it does not execute attachments.

Local commands

From the project directory in PowerShell:

python app.py
python -m detection.cli evaluate
python -m unittest discover -s tests -q
python research\validate_dataset.py

See the README for setup instructions and the research documents for definitions, limitations and available sources.

Known limitations

  • Instructor access is configured through environment variables; there is no public instructor registration.
  • Browser-session identifiers are pseudonymous, not verified people; clearing browser data starts a new identity.
  • The training library is fictional and the detection engine is rule-based. Neither replaces organizational reporting or professional security review.
